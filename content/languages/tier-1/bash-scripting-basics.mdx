## From Python to Bash: a different kind of language

You already know variables, conditionals, and loops from CS Foundations — the concepts don't change here, but the syntax and mental model do. Bash isn't a general-purpose language like Python; it's a language for gluing commands together. Every line is (usually) a command, and the shell's whole job is running programs and wiring their inputs/outputs to each other. That's the new material in this module: not "what is a loop" but "how does the shell actually work."

## Your first script

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "Hello from $(hostname)"
```

The `#!/usr/bin/env bash` line (the "shebang") tells the OS which interpreter runs this file. `set -euo pipefail` is a habit to adopt immediately:

- `-e` — exit the script the moment any command fails (nonzero exit code)
- `-u` — treat referencing an undefined variable as an error
- `-o pipefail` — if any command in a pipeline fails, the whole pipeline reports failure (by default, only the *last* command's exit code counts)

Without these three, scripts silently plow through errors — a classic source of "it deleted the wrong thing" bugs. Make it executable and run it:

```bash
chmod +x script.sh
./script.sh
```

## Variables: everything is a string, and spacing is load-bearing

```bash
name="Ada"
count=3
echo "Hello, $name. You have $count messages."
```

Two things that trip up every Python programmer:

1. **No spaces around `=`.** `name = "Ada"` is not an assignment — Bash parses it as running a command called `name` with arguments `=` and `"Ada"`, and you'll get a `command not found` error.
2. **There are no real types.** `count=3` stores the *string* `"3"`. Arithmetic needs explicit syntax: `$(( count + 1 ))` or `let count+=1`.

**Command substitution** — capturing a command's output into a variable — is the single most useful new idiom:

```bash
today=$(date +%Y-%m-%d)
files=$(ls *.log | wc -l)
echo "It's $today and there are $files log files."
```

`$(...)` runs the command in a subshell and substitutes its stdout, trimmed of trailing newlines. (The backtick form `` `cmd` `` does the same thing but nests badly — use `$(...)`.)

**Quoting matters more than it does in Python.** `"$name"` preserves the value as one token even if it contains spaces; unquoted `$name` gets word-split and glob-expanded by the shell. Default to double-quoting every variable reference unless you specifically want word-splitting.

```bash
file="my file.txt"
rm $file    # BUG: tries to remove two files, "my" and "file.txt"
rm "$file"  # correct: one argument
```

## Conditionals: `test`, `[ ]`, and `[[ ]]`

`if` in Bash doesn't check truthiness of a value — it checks the **exit code** of a command. `test` (usually spelled `[ ]`) is itself a command that evaluates an expression and exits 0 (true) or 1 (false):

```bash
if [ "$count" -gt 5 ]; then
    echo "busy day"
elif [ "$count" -eq 0 ]; then
    echo "nothing yet"
else
    echo "normal"
fi
```

Note `-gt`, `-eq`, `-lt` for *numeric* comparison — `>` and `<` inside `[ ]` do lexical string comparison (and can even redirect to a file, silently). For strings, use `=` and `!=`:

```bash
if [ "$1" = "prod" ]; then
    echo "deploying to production"
fi
```

Modern Bash gives you `[[ ]]`, an improved, non-POSIX version that's safer (no word-splitting surprises, supports `&&`/`||`/`=~` for regex directly) — prefer it when you don't need POSIX `sh` compatibility:

```bash
if [[ -f "$1" && "$1" == *.log ]]; then
    echo "$1 is a log file that exists"
fi
```

Common file-test flags: `-f` (regular file exists), `-d` (directory exists), `-e` (exists, any type), `-x` (executable), `-z`/`-n` (string is empty/non-empty).

## Loops: `for` and `while`

`for` over a list or a glob — this is the workhorse for batch operations:

```bash
for file in *.txt; do
    echo "Processing $file"
    wc -l "$file"
done
```

`for` over a range or explicit list:

```bash
for i in {1..5}; do
    echo "attempt $i"
done
```

`while` reading a command's output line by line is the idiom for processing files or command output (don't loop over `$(cat file)` directly — it word-splits on whitespace, breaking on filenames with spaces):

```bash
while read -r line; do
    echo "> $line"
done < input.txt
```

`while` with a condition, same shape as Python:

```bash
retries=0
while [ "$retries" -lt 3 ]; do
    echo "attempt $((retries + 1))"
    retries=$((retries + 1))
done
```

## Positional arguments: how scripts take input

Inside a script, `$0` is the script's own name, `$1`–`$9` (and `${10}`+ with braces) are the arguments passed on the command line, `$#` is the argument count, and `$@` is all arguments as separate words (`"$*"` joins them into one string — almost never what you want).

```bash
#!/usr/bin/env bash
set -euo pipefail

echo "Script: $0"
echo "First arg: $1"
echo "Arg count: $#"
echo "All args: $@"

for arg in "$@"; do
    echo "- $arg"
done
```

```
$ ./greet.sh Ada Grace Linus
Script: ./greet.sh
First arg: Ada
Arg count: 3
All args: Ada Grace Linus
- Ada
- Grace
- Linus
```

Always quote `"$@"` (not `$@`) when iterating — it preserves each argument as a separate item even if one contains spaces. `shift` drops `$1` and renumbers the rest, useful for parsing flags one at a time in a loop.

## Piping and chaining commands

The pipe `|` feeds one command's stdout into the next command's stdin. This is Bash's core superpower — composing small tools instead of writing one big program:

```bash
ps aux | grep python | awk '{print $2}' | sort -n
```

Read that right-to-left conceptually: list processes → filter to ones mentioning "python" → pull out column 2 (PID) → sort numerically.

`&&` runs the next command only if the previous succeeded (exit code 0); `||` runs it only if the previous failed:

```bash
mkdir -p backup && cp *.log backup/ && echo "backup done" || echo "backup FAILED"
```

Every command has an exit code, accessible right after as `$?`. `0` means success; anything else is an error code you can branch on.

## Putting it together: a real automation script

A script that backs up log files, reports how many it archived, and fails loudly if there's nothing to do:

```bash
#!/usr/bin/env bash
set -euo pipefail

if [ "$#" -lt 1 ]; then
    echo "Usage: $0 <directory>" >&2
    exit 1
fi

target_dir="$1"
backup_dir="${target_dir}/backup_$(date +%Y%m%d)"

if [ ! -d "$target_dir" ]; then
    echo "Error: $target_dir is not a directory" >&2
    exit 1
fi

log_count=$(find "$target_dir" -maxdepth 1 -name "*.log" | wc -l)

if [ "$log_count" -eq 0 ]; then
    echo "No log files found in $target_dir"
    exit 0
fi

mkdir -p "$backup_dir"

for log in "$target_dir"/*.log; do
    cp "$log" "$backup_dir/"
done

echo "Backed up $log_count file(s) to $backup_dir"
```

Every piece you just learned shows up here: `$#`/`$1` for arguments, `[ ]` tests for validation, command substitution to build a dynamic directory name, a `for` loop to do the copying, and `>&2`/`exit 1` for proper error signaling (never `exit 0` on an error path — callers and CI systems check that code).

## Exercise

Write `word_report.sh` that:

1. Takes one required argument: a file path.
2. If no argument is given, or the file doesn't exist, prints a usage message to stderr and exits with code 1.
3. Prints the file's line count, word count, and the 3 most common words (case-insensitive, ignoring punctuation) in the format:
   ```
   Lines: 42
   Words: 310
   Top words:
     the: 18
     a: 12
     to: 9
   ```

**Hint:** `wc -l` and `wc -w` get you the counts. For "top words," pipe the file through `tr` to lowercase and strip punctuation into one-word-per-line, then `sort`, `uniq -c`, and `sort -rn` chained together — that's five commands in one pipeline, which is exactly the kind of composition this module is about.
